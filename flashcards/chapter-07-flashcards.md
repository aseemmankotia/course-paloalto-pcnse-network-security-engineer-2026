## Chapter 7: Panorama: Templates, Template Stacks, and Device Groups — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Template stack override precedence — which template wins for overlapping settings? | The template listed at the TOP of the stack order wins for any overlapping setting. Exam tip: reorder templates with the up/down controls in the stack configuration to control precedence. |
| 2 | Device group hierarchy root level name? | Shared. Objects/policies defined here apply to ALL device groups unless a device group (or an ancestor closer to it) defines a same-named object that overrides it. Exam tip: 'same name at a lower level' = intentional override, not an error. |
| 3 | Full order of security rule enforcement on a Panorama-managed firewall? | Shared pre-rules → Device group pre-rules (top-down through hierarchy) → Local firewall rules → Device group post-rules → Shared post-rules → Default (implicit) rules. |
| 4 | Commit to Panorama vs Push to Devices — key difference? | Commit to Panorama saves the candidate config into Panorama's own running config only. Push to Devices separately sends that config to managed firewalls. Committing does NOT automatically push. |
| 5 | How do you override an inherited Shared object at a lower device group level? | Create a new object with the SAME NAME in the more-specific device group. The lower-level (more specific) object takes precedence for firewalls in that device group and its descendants. |
| 6 | Panorama's three operating modes? | Panorama (default: management + optional local log collection), Log Collector (dedicated log collection only, no full management UI), Management Only (device management, no local log storage). Configured under Panorama > Setup > Management. |
| 7 | When should you deploy a Dedicated Log Collector instead of using Panorama as Log Collector? | When log volume or the number of managed firewalls exceeds what Panorama's own local storage/processing can handle. Dedicated Log Collectors (M-Series or Panorama VM in Log Collector mode, in a Collector Group) scale log storage independently of the management server. |
| 8 | Template Variables — what problem do they solve? | Allow one shared template to push device-specific values (e.g., a different interface IP per firewall) instead of a single static value, letting the same template be reused across many sites. |
| 9 | Pre-rulebase vs Post-rulebase purpose | Pre-rules: mandatory/global rules enforced BEFORE a firewall's local rules. Post-rules: catch-all/cleanup rules enforced AFTER local rules (e.g., a logged deny-all). Exam tip: post-rules never run before local rules. |
| 10 | Where do you assign a firewall to a template stack? | Panorama > Templates > Template Stack — add the firewall as a managed device to the stack. A firewall can belong to only one template stack at a time. |
| 11 | What happens if you Commit to Panorama but never Push? | The firewall keeps enforcing its LAST pushed configuration. The newer config committed to Panorama is not applied to any device until an explicit push is performed. |
| 12 | Shared object override rule of thumb | The most-specific same-named object (closest to the firewall in the device group hierarchy) always wins over Shared or higher-ancestor versions. Same-named objects at different levels are an intentional override mechanism. |
